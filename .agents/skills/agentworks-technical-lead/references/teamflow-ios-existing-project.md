适用于已有业务工程的迭代、缺陷修复和重构。需求记录、实施验收、状态与授权统一遵循 [WORKFLOW](../../agentworks-director/references/teamflow-core-workflow.md)；本专题只补充工程定位与影响分析。

## 识别工程与目标

先读 Git 状态、AGENTS.md 和已有项目说明，结合 `.xcodeproj`、`.xcworkspace`、Package.swift、工程生成配置、源码和 CI 判断工程类型。没有 PRD 或 `.xcodeproj` 不代表新产品或空目录；区分业务 App、组件包和工作流工具仓库。

多 App、Target 或 Scheme 时，从需求和现有资料定位本次目标；仍无法确定时仅询问这个关键选择，可继续阅读共同配置。不创建第二个 App 或嵌套 Git 仓库。已有仓库中明确新建独立产品时，对新产品使用 [启动模板](../../agentworks-product-manager/references/teamflow-ios-templates-new-project.md)。

## 复用工程资料

已有项目说明、架构记录或构建文档足以定位本次工作时，直接读取并从需求卡引用，无需新建 `PROJECT-CONTEXT.md`。只有信息缺失或入口分散、需要持续维护索引时，才按 [项目现状模板](teamflow-core-templates-project-context.md) 创建或补充该文件；已有材料使用链接。

只补充本次需要的稳定事实：工程入口、目标、语言/UI 框架、架构目录、部署目标、依赖和验证配置入口。按章节记录来源与核对日期，未知项不套用新项目默认值，不为填满模板扫描全仓。后续仅核对本次相关配置；事实改变时更新原资料或索引条目及原因，不重复建立记录。

普通项目直接搜索入口、相关符号与调用者。大型工程已启用索引或明确需要时使用 [MODULE-CONTEXT](teamflow-core-module-context.md)。项目资料只链接 `.agents/project-modules.json`，不复制模块字段、基准或动态状态；实际工程与影响分析优先。

## 沿用配置与分析影响

沿用实际语言、UI 框架、架构、最低系统、依赖管理、导航、主题、语言和签名配置，优先复用现有组件与测试模式。已有明确约定优先于通用规范；基础配置确需调整时，将变化、影响和理由纳入需求范围。

按本次风险检查相关页面、组件、调用者、接口、存储、权限、订阅、多语言与打点，省略无关项。共享组件需检查使用方；存储迁移、认证或订阅权益需考虑已有用户、兼容性与恢复路径，不能以卸载重装代替。

## 工程基线与回归

按改动选择最小有用基线：缺陷尽量复现，工程或依赖调整先确认相关构建，纯文档不要求 App 构建。命令与证据按 [CHECKS](../../agentworks-qa-engineer/references/teamflow-core-checks.md) 管理，已有日志直接引用，不再抄写命令、设备和结果。不重置用户数据或清理已有改动。

区分原有失败与本次引入的问题；原有失败若阻止关键验收，明确限制并保留未完成 AC。回归覆盖本次功能及实际受影响路径，不默认全仓、全设备或超大字号矩阵；已有验收要求仍执行。避免无关迁移、格式化、依赖升级和机械重构。
