# 游戏发布与外部动作

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/skills/Godot/references/RELEASE.md`。保留专业规范并调整资源链接；文中的 TeamFlow 专属命令/路径仅适用于已安装原工具的业务工程，不能据此声称当前仓库已安装它们。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

只在用户明确提出准备或执行导出分发包、上传平台、提审或上线时加载。授权原则见 [WORKFLOW](../../agentworks-director/references/teamflow-core-workflow.md#授权与停止)，凭据与外部服务见[共用边界](../../agentworks-director/references/teamflow-core-boundaries.md)。iOS 目标在 Godot + iOS 模式下改用 iOS 发布规则，经 [Godot 与 iOS](teamflow-godot-ios.md) 进入。

## 动作边界

| 用户表达 | 允许范围 |
| --- | --- |
| 检查/准备发布 | 只读核对导出预设、模板、签名配置、商店元数据与缺项，不导出、不上传 |
| 导出指定平台的发布包 | 用明确预设导出并核对产物，不上传 |
| 上传到平台测试渠道（如 Google Play 内部测试、Steam 非默认分支、TestFlight 以外的测试轨道） | 只上传到指定渠道，不推广到公开轨道 |
| 提交平台审核 | 只提交指定版本与构建，不自动上线 |
| 上线/推广到公开渠道 | 只发布已明确的版本、渠道和地区，含分阶段比例 |
| 回滚、下架或撤回 | 只处理明确的版本、渠道和地区 |

一次可明确多个目标；只要求后面的目标时，可自动补齐确实缺失的导出或上传前置，到目标即停。平台、渠道、版本号、构建号、账号或地区无法确定时先询问，不猜测。

## 准备与凭据

- 导出使用 `export_presets.cfg` 中的明确预设和与工程同版本的导出模板；Debug 导出不能用于正式分发。
- Android 签名 keystore、Steam/商店令牌、Web 托管密钥只用团队既有密钥管理或 CI secret；不提交、不写入需求卡、日志或命令回显。导出凭据位置见[团队协作](../../agentworks-technical-lead/references/teamflow-godot-team.md#导出配置与凭据)。
- 每次正式导出核对版本号与构建号递增规则（如 Android `version/code`），不复用已上传的构建号。
- 商店要求的隐私声明、年龄分级、数据安全表单与广告/同意机制按目标平台实际要求核对；未确认的列为缺项，不宣称准备完成。

## 结果记录

完成或失败后，在当前需求卡“决策与异常”追加含时区记录：动作、平台/渠道/地区、版本与构建号、完整 commit、结果（失败、平台处理中、已完成）和可定位链接。处理中不能记为可分发；重新导出产生新构建，旧构建的测试或审核结论不能自动沿用。上传成功不等于审核通过，审核通过不等于上线，GitHub Release 不等于商店发布。
