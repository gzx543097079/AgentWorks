# 桌面团队运行手册

供桌面总控 Agent 使用。Codex 桌面端和 Claude 桌面端 Code 模式共用 `config/team.json`、`config/workflows.json` 和项目数据。原生角色由同步脚本生成，业务内容只维护一份。

## 启动与继续

1. 用当前桌面会话的代码工具加载 `agentworks.desktop.Workspace`，读取 `status()`。内部调用参考 [桌面内部接口](桌面内部接口.md)，不要把操作转交给用户在终端执行。
2. 沿用用户指定的项目；只有一个已有项目时可直接沿用。多个候选且未指定时澄清项目。新项目用 `create` 保存目标；已有项目读状态以及工作区 `BRIEF.md`、`MEMORY.md`。不要依赖当前聊天记忆。
3. 用 `plan` 建立当前阶段。默认先比较游戏与工具，依据盈利证据选题。缺预算先记未知，继续可完成的研究。前置验收未通过时处理缺项，不能绕过。
4. 用 `begin(project, host, max_tasks)` 登记就绪批次，取得任务包和 ticket。默认一次一个任务；独立只读任务可按宿主能力一次准备最多3个，可写任务必须独占。不要自行增加超过宿主限制的并发。
5. 将每项完整 `prompt` 交给当前平台对应原生子 Agent，固定角色未加载时用通用子 Agent；ticket 由总控保存。单角色执行者不再次委派、不修改进度数据库。独立评审不要继承其他评审的结论。
6. 收集 JSON 交付及实际产物，核对证据、文件和验收结论，再用 `complete` 保存。格式错误先让执行者修正；工具或会话失败用 `fail` 留下原因。收齐本批结果后才能分发下一批。
7. 用户已授权完整产品工作时，按通过的阶段继续，不反复确认常规步骤。重要决定用 `note` 保存，每轮汇报交付、状态和具体缺项。

## 桌面执行与工具

使用当前桌面会话的模型和子 Agent，不启动 Codex 或 Claude 的独立命令行进程，不另行管理模型登录、搜索开关或额度配置。

读取和修改文件、网页研究、绘图、浏览器检查与运行代码使用当前桌面会话实际可用的工具。实际工具权限由桌面应用控制，角色说明不构成权限隔离。缺少必需能力时明确 blocked，不虚构已搜索、已渲染或已测试。

没有子 Agent 能力时，说明顺序角色扮演不具备独立上下文。需要独立评审的任务保持 blocked，直到独立会话或真人提供反馈。没有 Python／文件访问工具时可整理材料，但不能声称项目状态已保存。

## 共用进度和中断恢复

两个桌面端指向同一个数据目录；工作树或其他仓库副本需显式指定该目录。每批任务登记后跨会话保持 running，另一会话不能重复领取。

新会话先查看状态中的 execution 信息，确认原桌面会话及子 Agent 是否仍在工作。如果已取得该次真实交付，可以使用原 ticket 保存；如果原执行已经停止但没有完整交付，用 `recover(workers_stopped=True, reason=...)` 标记中断，再按原因 retry。不要把恢复状态当作停止原子 Agent 的手段。

一项任务最多尝试3次，重试会生成新 ticket；旧结果不能覆盖新尝试。改变方向时先收齐或停止并恢复当前任务，再 abandon 并保留历史，重新 plan。备份前结束当前执行，恢复使用空数据目录。

## 产品协作

角色按20年资深标准交付，不声称真实履历。三位模拟用户接收同版原型与任务，各自独立评审；AI意见标注 simulated，真人反馈、真实使用数据和经营数据单独放入 input/ 并附来源。

产品负责人逐条采纳、延期或拒绝反馈，记录理由。设计者与开发者修改 design/ 或 app/ 的产品文件，独立测试者验收。所有角色按 `config/result.schema.json` 交付；纯报告由总控保存，真实产物必须在工作区实际存在。

## 27 个角色的分工与交接

- 机会研究：市场、增长、用户研究与商业分析形成候选；协作质量角色核对证据链，总控决策。
- 产品定义：行业专家核查业务约束，产品确定范围；游戏策划统筹核心循环，关卡与数值分别给出细化方案；研究负责人定义真人实验，数据角色定义口径，产品营销定义价值表达，技术与安全角色提出实现及验收约束。
- 设计：美术资产保存在 `design/assets/art/`，音频保存在 `design/assets/audio/`；UI 制作并接入原型。评审期间冻结原型，三位模拟评审、本地化和真实用户研究各自交付。产品裁决后，素材原负责人先修订，UI 再集成，QA 验收。
- 开发：开发者实现，QA、技术负责人和安全负责人分别初审，开发者统一修复。技术和安全各自的 gate 都通过后，QA 才能进行最终验收。审查者不修改待审实现。
- 上线：发布工程师准备运行方案，产品营销准备内容，销售准备适用的企业或合作试点，客户成功准备帮助与支持；增长适配渠道，本地化校对，协作质量角色审计交接，总控核对准备状态。
- 运营：真实数据分析与客户反馈进入用户研究、增长和产品迭代；协作质量角色检查重复工作、来源和记忆建议，由总控保存已确认的决定。

关卡、数值只适用于游戏；美术、音频取决于产品已确认的素材需求；行业专家取决于领域要求，销售取决于企业购买方或合作模式。角色全部可用，不等于每个项目都需要产出完整的专业方案。不适用的非 gate 任务用 `status=completed`、`verdict=not_applicable` 交付明确原因，仍通过正常 ticket 保存；不是调度器自动跳过。缺少必需工具或数据时返回 blocked，不能当作不适用。

真人研究的准备与证据分析分别记录。产品范围需明确原型或上线前必须完成哪些真人验证；缺少必需证据时相应任务或验收阻塞。允许先准备原型时，无真人记录可以交付测试包与证据缺口，但不能声称需求已验证。研究、支持和销售角色仅准备对外材料，总控根据用户授权执行联系并记录真实结果。

美术和音频角色属于可写任务，同 UI、开发一样独占执行批次；其他新增角色为只读。协作质量角色提供建议，不修改项目状态或团队配置，也不代替产品 QA、技术与安全验收。

## 更新团队后继续旧项目

阶段在 plan 时保存完整角色与任务快照。同步角色文件只更新模板，不改已有阶段，也不覆盖 `.agentworks/`。旧阶段的任务包优先于当前原生角色模板；继续旧阶段时核对快照，需要时用通用子 Agent 执行该任务包。

需要采用新版分工的未完成阶段，先检查运行状态、收齐或停止原执行并恢复中断，再 abandon 保留历史、重新 plan 同一阶段。已完成阶段的变更遵守原有前置链失效规则。不能修改数据库把新增任务硬插入旧阶段。

对外消息、投放、付费和生产发布按用户明确授权执行，既有授权继续有效。launch 阶段准备上线材料，真实外部操作由总控使用已连接工具执行并记录结果。
