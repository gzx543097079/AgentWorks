# 按模块增量理解工程

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/teamflow-core/references/MODULE-CONTEXT.md`。已将状态、命令与职责适配为 AgentWorks。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

先读已有工程约定、目录、入口与当前差异，再按需求定位职责、实际调用者和必要依赖。稳定模块表包含职责、触发词、路径、入口符号、依赖、调用方和验证入口；只保留一份，由技术负责人建议、开发维护。

索引只帮助定位，不能代替阅读待改符号。关键词未命中、路径移动/删除、共享依赖或构建配置变化时扩大到真实影响面；不能静默判成无变化。相似模块名不等于同一业务语义。

核对基线提交与已提交、暂存、未暂存及未跟踪变化，避免只看 HEAD 丢失现场。当前基线干净只说明无差异，不代表已理解实现。模块职责变化同步真实索引，不把每轮动态结果复制进稳定项目说明。

业务工程已有 TeamFlow module 工具时可以继续使用其 project-modules 索引；本技能不安装该命令。无工具时从现有代码完成上述核查，交付可定位的路径、符号和影响面。禁止凭空声称执行了 module inspect。
