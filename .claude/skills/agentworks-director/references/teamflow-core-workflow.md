# 需求推进与交接

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/teamflow-core/references/WORKFLOW.md`。已将状态、命令与职责适配为 AgentWorks。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

咨询、只读评审和不改变行为的轻量修改按任务直接处理。涉及行为、依赖、配置、权限、付费、数据或 API 的修改，在产品交付中固定需求编号、范围、不包含和可观察验收条件（AC）。AgentWorks 的 run/task/ticket 是唯一调度状态；不另建 TeamFlow 状态库。

新 App 的平台、市场、架构和工具链先形成可审阅方案；已明确的偏好直接执行。既有项目新增模块、跨模块接口、数据迁移或重大取舍超出已授权范围时，把影响与可选方案交给主会话；已有授权继续有效，不重复确认。

实施先跑最小相关检查，收尾核对当前产物与 AC；已有同输入有效证据可复用，不机械重复全量测试。人工 AC（真人体验、真机、账户、业务效果）只有实际记录或用户确认才能完成，不用 AI 推断、模拟器或计划替代。

主会话登记 begin、收集单角色结果并 complete；worker 不改全局状态、不自行 commit/push 或完成整个需求。角色报告完成与需求验收通过分开。阻塞记录具体缺项和恢复入口，取消或扩大范围依照用户决定。失败重试保留原 ticket/报告关联，不抹除旧失败。

同一产品写任务由现有调度独占；并行代码修改只有在主会话已安排隔离工作区、合并负责人和复核方案时进行。独立评审互不读取同轮意见。

每次交接给出需求/AC、当前版本、真实证据、未决事项、下一负责人和下一动作；有事实才写决策和异常，不预造日志。跨平台沿用同一数据目录和已保存状态，不能靠聊天记忆恢复。
