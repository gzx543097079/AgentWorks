# 缺陷与团队改进

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/teamflow-core/references/REPAIR.md`。已将状态、命令与职责适配为 AgentWorks。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

缺陷报告先记录触发条件、期望、实际、影响、受影响版本和可复现证据，有事实才补根因与失败尝试。同一缺陷复发沿用问题编号、重开受影响 AC；独立根因另立项。开发修复后由 QA/技术/安全相应职责复核原失败场景及受影响回归。

流程改进只针对已复现流程缺陷、重复返工或用户明确纠正。先定位最小根因，优先修正旧规则，避免叠加第二套台账。保留可比较的前后场景；有真实用量/时长才计算成本，不承诺虚构提升比例。

纯措辞调整不增设无行为价值的测试。改进失败时撤销本次可归因改动，保留原数据和失败依据。质量角色提出改进建议，修改框架作为单独维护任务，不自行重写团队配置、历史状态或用户授权。
