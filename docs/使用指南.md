# 桌面使用指南

AgentWorks 用于 Codex 桌面端和 Claude 桌面端的 Code 模式。你在聊天里提出任务，桌面 Agent 读取团队规则，分配角色、处理交付并保存进度。

目前共有 27 个角色，全部按20年资深标准工作。新增了真实用户研究、技术审查、安全隐私、美术、音频、关卡、数值、产品营销、客户成功、行业专家、销售商务及 Agent 协作质量评估。按产品和阶段分工，不适用的任务记录原因。

## 第一次打开

**Codex 桌面端**：把 AgentWorks 文件夹作为本地项目打开，在该项目中新建聊天。

**Claude 桌面端**：进入 Code 模式，选择本地 AgentWorks 文件夹，开始会话。

两边选择同一份原始文件夹，就能接续同一个项目。不要把仅名称相同的仓库副本或新工作树误认为原来的数据目录。

第一次可以直接说：

> 读取项目规则，检查 AgentWorks 是否准备好，列出已有项目。先不要启动市场研究。

Agent 会核对角色、流程、数据目录和当前工具能力。你不需要安装独立模型命令行，也不需要输入终端命令。模型、账号和工具权限使用当前桌面应用的设置。

## 开始与继续

| 你想做什么 | 在两个桌面端都可以这样说 |
|---|---|
| 新建项目 | 使用 AgentWorks 新建海外产品项目，先比较游戏和工具，再按盈利证据选择方向。 |
| 查看进度 | 查看 AgentWorks 的项目和当前进度，告诉我完成了什么、还缺什么。 |
| 接续工作 | 继续 first-opportunity，从已保存进度开始。 |
| 评审原型 | 让三位模拟用户独立评审当前原型，由产品负责人汇总并裁决修改意见。 |
| 开发验收 | 根据已通过的需求和原型开发，安排独立测试并修复问题。 |
| 准备运营 | 为当前产品准备上线材料和第一轮增长实验。 |
| 保存决定 | 记住这个项目的目标市场是英语用户，先验证工具类产品。 |
| 备份项目 | 把这个项目及其进度备份到我指定的文件夹。 |

技能快捷入口是可选的：Codex 为 `$agentworks`，Claude Code 为 `/agentworks`。不记快捷命令也能用自然语言启动。

## 六个阶段

| 阶段 | 交付 |
|---|---|
| 机会比较 | 游戏与工具机会、需求与付费证据、渠道、验证成本和候选方向 |
| 产品定义 | 领域与需求、玩法与关卡数值、真实用户研究计划、技术与安全方案 |
| 设计评审 | 适用的美术音频、实际原型、独立模拟评审、真人测试包、本地化、修改和验收 |
| 开发测试 | 代码、独立测试、技术及安全审查、修复、独立复核与回归 |
| 上线准备 | 发布恢复、营销内容、适用销售试点、支持帮助、交接审计与准备结论 |
| 运营迭代 | 真实数据与支持反馈、用户研究、运营实验、产品迭代与协作复盘 |

阶段验收通过后再推进下一阶段。20年经验是角色的专业判断标准；AI评审始终是模拟，不能替代真实用户与经营数据。

已有阶段保留原来的配置与进度，新建阶段使用更新后的团队。要让未完成阶段采用新版分工，可以说：“保留当前记录，检查正在执行的任务后，用新版团队重新规划当前阶段。”

## 安装到产品仓库

在 AgentWorks 会话里说“把 AgentWorks 安装到 ~/Desktop/Cleaner”，Agent 会运行 `scripts/install.py`：

- 复制 27 个角色、全部技能、团队手册和内部模块，内部文件放在 `Cleaner/.agentworks/engine/`；
- 在 `AGENTS.md`、`CLAUDE.md`、`.gitignore` 中追加带标记的 AgentWorks 区块，保留你原有的内容；
- 遇到同名但不是由 AgentWorks 安装的文件时停止，不写入任何内容。

之后直接在桌面端打开 `Cleaner`，说“使用 AgentWorks 新建项目，先比较游戏和工具”。该仓库就是产品工作区，只对应一个项目：

- `文档/01-机会研究/` … `文档/06-运营迭代/`：各阶段报告，如 `文档/02-产品定义/需求文档.md`；
- `文档/项目简报.md`、`文档/项目记忆.md`、`文档/输入资料/`：项目目标、已确认的决定、真实资料；
- `design/prototype/`、`design/ui/`、`design/art/`、`design/audio/`：原型、UI 设计稿、美术与动画、音频；
- `app/`、`release/`、`store/`、`marketing/`、`support/`：源代码、发布配置、商店素材、获客素材、帮助内容；
- `.agentworks/`：工具内部的状态库、任务包和执行凭据。

这些内容随产品仓库提交；锁文件和 `文档/输入资料/` 中的真实用户资料默认不提交。每个阶段验收通过后，团队会提醒你提交。项目有任务正在执行时不能升级，安装程序会提示等当前批次交回。升级时在 AgentWorks 会话里再安装一次，已移除的旧文件会被清理，项目进度不受影响。不要手改 `.agentworks/engine/` 和 `agentworks*` 角色与技能文件，检查时会报告改动。

## 切换桌面应用

先让当前桌面 Agent 收齐并保存交付，再在另一个应用打开同一份文件夹，说“从已保存进度继续”。不用复制角色，不用迁移聊天历史。

项目仍有任务执行时，另一边会看到执行中状态，不应重复分发。应用退出或任务中断后，先确认原子 Agent 已停止，让新会话检查已有文件并恢复中断状态，再根据原因重试。

如果桌面端使用了独立工作树，请让 Agent 连接原来的项目数据目录；同名工作树不会自动拥有 `.agentworks/` 的进度。换电脑时，Git 同步系统定义，项目数据通过备份转移。

## 数据保存在哪里

以下是直接在 AgentWorks 仓库中运行的位置；安装到产品仓库的位置见上文。


- `config/`、`roles/`、`.codex/`、`.claude/`：共享团队及桌面原生适配，保存在 Git。
- `.agentworks/state.sqlite3`：项目、阶段、任务和事件记录。
- `.agentworks/projects/项目/workspace/`：简报、长期记忆、原始资料、原型及产品代码。
- `.agentworks/projects/项目/runs/`：任务包、桌面交接凭据、每次尝试的交付与报告。子 Agent 直接把交付写在这里，不经过临时目录。

`.agentworks/` 不随 Git 推送。备份包含项目数据和交付，可能含敏感资料；让 Agent 保存到你选定的位置。恢复使用空的数据目录，避免覆盖现有项目。

## 能力边界

桌面应用提供模型、子 Agent、搜索、图像、浏览器和开发工具；本仓库不自动连接不存在的能力。缺少必要工具或数据时，团队记录具体缺项。当前本地状态模块要求 Python 3.9+、Git，支持 macOS/Linux，由桌面 Agent 的代码工具调用。

当前没有部署常驻服务。关闭应用后能否继续运行取决于桌面平台和会话状态，本仓库不会另行启动后台模型进程。上线准备通过不表示已经发布；真实上线、发送消息或投放需要用户已给出的明确授权。
