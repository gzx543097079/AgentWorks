# AgentWorks 桌面团队

先读 [团队运行手册](../../../docs/团队运行手册.md)，以仓库根目录为工作目录。Codex 和 Claude 共用该手册、角色定义、工作流和项目进度。

读取已保存状态、简报和记忆，使用当前桌面会话的原生子 Agent 与工具协作。总控用 `agentworks.desktop.Workspace` 登记任务、保存交付和验收结果，调用方式见 [桌面内部接口](../../../docs/桌面内部接口.md)。不要要求用户操作终端，也不另行启动模型命令行。

单角色执行者只处理分配任务，总控负责落盘。独立评审使用不同上下文；没有子 Agent 能力时说明限制，不能将顺序角色扮演称为独立多 Agent。模拟用户意见不冒充真人验证。

用户操作见 [使用指南](../../../docs/使用指南.md)，产品决策和验收标准见 [协作约定](../../../docs/协作约定.md)。

任务包中的 `skills` 给出当前角色技能的绝对路径与资源指纹。分配时要求 worker 先读该入口，再按实际 iOS/Godot/其他平台加载相关规范；不把全部角色技能塞进每个上下文。手工分配角色时从 `config/team.json` 的 `skills` 字段找入口。技能职责与 TeamFlow 来源见 [职责与技能](../../../docs/职责与技能.md)。

用户确认关卡由总控展示具体版本后等待真人答复，通过 `review/confirm` 保存，不能委派给角色或用 AI 验收替代。修改时用 `revise` 重置受影响任务及下游，保留交付快照；产品版本通过 `set_version` 管理。具体状态与调用约束以桌面内部接口为准。

跨阶段修订会归档旧下游阶段并保存失效原因；源阶段通过后重新 plan 后续阶段。接续用 status.current_stage 定位当前工作；等待确认期间改文件必须重新交付和评审，不能仅刷新 review 沿用旧验收。
