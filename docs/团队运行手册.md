# 团队运行手册

供 Codex、Claude Code 和其他能读写仓库的 Agent 使用。角色源是 `config/team.json`，可读角色卡是 `roles/*.md`，任务与验收来自 `config/workflows.json`。宿主只提供模型和工具，项目进度由 AgentWorks 保存。

## 启动与继续

1. 从仓库根目录运行 `python3 -m agentworks status`。沿用用户指定项目；只有一个项目时可直接沿用，多个候选且未指定时澄清项目。
2. 新项目用 `create` 保存目标、市场和约束；已有项目读 `status 项目` 以及工作区的 `BRIEF.md`、`MEMORY.md`。不重复执行已完成任务。缺预算先记未知，继续可完成的证据收集。
3. 用 `plan 项目 阶段` 建立任务。默认先以 discovery 比较游戏和工具。前置未通过则处理缺项；用户已授权完整产品工作时按阶段继续，不重复确认常规步骤。
4. 用 `packet 项目 任务编号` 导出当前 ready 任务。任务包包含角色、简报、记忆、已完成前置交付、旧阶段交付索引和结果 Schema，可跨模型交接。
5. 执行角色交付后，总控先检查文件、证据和验收结论，把 JSON 保存到 `.agentworks/` 再 `submit 项目 任务编号 结果文件`。运行 `status` 确认保存成功后再调度下游。
6. 用 `note` 保存用户已确认的目标、约束和裁决；每轮汇报交付、进度及具体缺项。不要把当前聊天当作唯一记忆。

命令、状态和备份示例见 [使用指南](使用指南.md)。有自定义数据目录时，后续所有命令沿用同一个 `--data-dir`。

## 选择执行方式

**优先在当前会话中运行团队。** 不要求安装其他平台。支持子 Agent 时，将独立任务及完整任务包交给不同上下文；固定角色不可用时传给通用子 Agent。受宿主实际并发限制约束。角色完成后不得自行继续调度，总控负责提交。

**没有子 Agent 时**，同一模型按任务顺序扮演不同角色，报告注明“顺序角色模式，非独立多 Agent”。不能把已经看过前一份意见的同一会话声称为独立评审；需要独立评审的任务保持 blocked，直到在新会话、其他执行器或真实用户处获得独立反馈。不能为了进入下一阶段自行降低验收条件。

**终端自动执行是可选项。** `run --execute --backend codex` 或 `--backend claude` 调用独立 CLI；不在相同平台的交互会话内嵌套启动 CLI。后台与对话协作不同时执行同一项目。任务完成后可以切换宿主继续，失败任务先检查再 retry。

**缺能力时**，保留已完成材料并返回具体 blocked，不伪造搜索、渲染或实际测试。没有 Python／终端工具时可生成报告和 JSON 供导入，但不能声称状态已保存。其他客户端的工具名、权限、登录和技能发现由该客户端提供，本仓库不会赋予不存在的能力。

## 角色交接和隔离

- 全部角色按20年资深标准交付，这是专业判断框架，不能冒充真实履历。
- 三位模拟用户接收同一版原型及任务，不读取同轮其他评审。意见标注 `simulated`；真人反馈和真实经营数据单独存入项目 `input/` 并注明来源。
- 产品负责人去重并逐条采纳、延期或拒绝意见；设计者和开发者按裁决修改，测试者独立验收。
- 单角色 worker 不再委派。可写任务按顺序执行；独立只读任务可并行。只修改分配的产品工作区，原型在 `design/`，实现位于 `app/`。
- 任务包及结果是跨环境交接依据；不导入平台私有聊天数据库或登录凭证。换电脑先备份／恢复项目数据，单独克隆 Git 只能得到系统定义。

## 阻塞与授权

blocked 或 needs_revision 时先保存具体问题。补充输入或修复后带原因 retry，最多3次；改变方向保留历史并 abandon 当前轮，再 plan。验收角色不能通过篡改结果掩盖失败。

对外消息、投放、付费和生产发布按用户明确授权执行；已给的授权继续有效。后台 launch 只准备材料，真实外部执行由有连接和权限的交互会话完成，并保存实际结果。
