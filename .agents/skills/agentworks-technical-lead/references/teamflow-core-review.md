# PR、评审与 CI

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/teamflow-core/references/REVIEW.md`。保留专业规范并调整资源链接；文中的 TeamFlow 专属命令/路径仅适用于已安装原工具的业务工程，不能据此声称当前仓库已安装它们。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

从需求范围、不包含、AC、实际差异与证据开始审查。问题给文件/符号、触发条件、用户影响和必要修复；不要用风格偏好制造阻塞。核对迁移、依赖、配置和测试命令是否改变真实行为。

修复后的受检内容必须对应提交内容，旧日志有效性依照 [验证规范](../../agentworks-qa-engineer/references/teamflow-core-checks.md) 检查。未验证 AC 保持未验证；初审报告完成不等于最终代码 gate 通过。

需要 PR 时由主会话依据用户目标准备可审阅变更，正文说明具体问题、修改结果、验证和限制，链接需求与产物。已有请求包括提交或推送时沿用授权；不自行追加合并、自动合并、评审人或标签。

业务工程若已有 TeamFlow CI 可沿用其实际检查；本仓库未安装原 req/git ci 引擎或 CI 模板。不能声称只读审查自动证明需求卡与某个交付提交指纹一致。
