## 注释写什么

- 新增类型和非平凡方法说明职责、使用前提或结果；公开接口使用文档注释，必要时说明参数单位、返回值、失败与取消语义。
- 复杂分支、算法、业务限制、并发/线程要求、所有权和生命周期、临时兼容方案，解释“为什么”和不能破坏的约束。
- 属性仅在用途、单位、边界或所有权不直观时补充说明；简单赋值、直观访问器和常规布局不逐行翻译代码。每个有独立职责的新组件至少说明职责，避免只有文件头而没有关键逻辑解释。
- 注释与实现一起维护；改变行为时删除或修正过时说明，不写未经验证的性能、线程安全或内存保证。TODO/FIXME 只用于确实未完成且允许保留的事项，附需求编号或解除条件，不用它掩盖阻塞问题。

## 语言习惯

Swift 使用 `///` 描述类型和接口，复杂契约按需写 `- Parameter`、`- Returns`、`- Throws`，字段标题保留工具格式，说明用中文。Objective-C 头文件使用 `///` 或 `/** ... */`，实现内使用 `//` 解释局部意图；避免在头文件和实现重复同一段说明。

```swift
/// 取消上一次请求，避免旧响应覆盖用户最新选择。
func reloadSelection() { /* 实现按实际项目填写 */ }
```

```objc
/// 返回缓存快照；由调用者决定是否触发后台刷新。
- (nullable NSArray<NSString *> *)cachedItems;
```

注释不包含凭据、真实用户信息或未脱敏业务数据。用户可见文案仍走本地化资源，中文代码注释不改变按目标市场确定的 App 语言配置。
