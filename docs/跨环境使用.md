# 在 Codex 和 Claude Code 中使用

AgentWorks 当前维护 Codex 和 Claude Code 两个平台。两边读取同一套角色、流程、交付协议和项目进度，优先使用各自的原生子 Agent；独立 CLI 运行器是可选方式。

## 只维护一份团队配置

`config/team.json` 是唯一角色源，`config/workflows.json` 是唯一工作流源。修改后运行 `python3 scripts/sync_agents.py`，自动生成两边的角色配置。不要直接修改生成文件；它们不是两套需要分别维护的团队。

```text
config/team.json（唯一角色源）
          ↓ 同步生成
          ├── .codex/agents/*.toml
          ├── .claude/agents/agentworks-*.md
          └── roles/*.md（共用角色卡）

AGENTS.md（共用团队规则）← CLAUDE.md 导入
.agentworks/（共用项目记忆、交付与进度）
```

## 入口与角色适配

| 环境 | 项目入口 | 角色 | 调用方式 |
|---|---|---|---|
| Codex | `AGENTS.md` | `.codex/agents/*.toml` | 自然语言，或 `$agentworks` 技能 |
| Claude Code | `CLAUDE.md` 导入 `AGENTS.md` | `.claude/agents/agentworks-*.md` | 自然语言，或 `/agentworks` 技能 |

两边的文件格式不同，因此保留各自的原生入口。Claude Code 通过 `CLAUDE.md` 的导入方式读取共享规则。依据：[Codex 项目指令](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Claude 项目指令和文件导入](https://code.claude.com/docs/en/memory)。仓库里的单数 `AGENT.md` 仅保留为历史指引，正常使用这两个平台不需要它。

打开仓库根目录后，直接输入：

> 请读取 AGENTS.md，使用 AgentWorks 查看当前项目，从已保存进度继续。优先使用当前环境的子 Agent 和工具。

两个平台都可以用这句话启动；`$agentworks` 和 `/agentworks` 只是可选快捷入口。如果技能没加载，显式读取 `docs/团队运行手册.md`；固定角色没加载时给当前平台的通用子 Agent 传完整任务包。如果当前会话没有子 Agent 能力，要明确说明，不能把同一上下文的顺序扮演声称为独立评审。

## 同一个项目切换环境

同一台电脑、同一份仓库：先结束当前执行，检查 `status`，再用另一个宿主打开该目录；完成交付后 `submit` 保存，再继续下一个 ready 任务。CLI 和原生会话共用同一个状态库，不按模型复制项目。进程异常退出用 `recover`，确认产物后 `retry`。

不同电脑或不同仓库副本：Git 同步系统定义；使用 `export` / `restore` 转移项目数据。`.agentworks/` 被 Git 忽略，只克隆仓库不会带来已有项目进度。不要用云盘并发同步正在写入的 SQLite 状态库。

## 可选 CLI 后端

在仓库根目录的独立终端执行：

```bash
python3 -m agentworks run my-product --execute --backend codex --max-tasks 2
python3 -m agentworks continue my-product --execute --backend claude --max-tasks 1
```

`--backend auto` 是默认值：仅安装一个 CLI 时选择它；同时安装多个时要求显式选择，避免意外使用另一账号。所选 CLI 缺失不会静默切换平台。`--model` 的值由对应 CLI 解释，省略则沿用该 CLI 的设置。每次执行在日志中记录后端。

| 能力 | Codex 后台 | Claude 后台 | 当前宿主会话 |
|---|---|---|---|
| 结构化交付与依赖交接 | 支持 | 支持 JSON Schema 接口 | 通过 packet / submit |
| 独立角色上下文 | 每任务独立进程 | 每任务独立进程 | 取决于子 Agent 能力 |
| 文件与 Shell | Codex 沙箱按角色控制 | 读文件；可写角色允许 design/、app/ 编辑；不提供 Shell | 按宿主工具和权限 |
| 搜索 | 默认请求开启 | 默认提供 WebSearch / WebFetch | 取决于宿主与连接 |
| 图像、浏览器、外部服务 | 取决于已配置工具 | 此后台适配不开放 MCP | 按已连接工具和授权 |

Claude 后台使用 `dontAsk`，不绕过权限；缺少权限时任务失败或 blocked。需要运行构建、测试、截图或图像生成时，在有对应工具的交互会话接续，不能把静态检查当作运行验收。`--no-search` 控制内置搜索能力，不是隔离网络的开关。两个平台的权限模型不同，提示词和角色文件不构成强制隔离。

Claude 子 Agent 文件使用 Markdown frontmatter，技能放在 `.claude/skills/`；CLI 接口使用 `-p`、`--output-format json`、`--json-schema`，提取 `structured_output`。配置依据：[子 Agent](https://code.claude.com/docs/en/sub-agents)、[技能](https://code.claude.com/docs/en/skills)、[程序化执行](https://code.claude.com/docs/en/headless)、[CLI 参数](https://code.claude.com/docs/en/cli-reference)。

## 单一来源和维护

- 角色只编辑 `config/team.json`。运行 `python3 scripts/sync_agents.py` 生成通用角色卡及两种平台配置。
- 技能源只编辑 `.agents/skills/agentworks/SKILL.md`；同步脚本复制到 Claude 技能目录，两边共用同一个运行手册。
- 用 `python3 scripts/sync_agents.py --check` 检测漂移和已移除角色的残留配置。不会删除自行添加的、没有生成标记的角色。
- 工作流和结果协议分别维护在 `config/workflows.json` 与 `config/result.schema.json`，两边共用，不按平台复制。

验证范围见 [验收记录](验收记录.md)。本机尚未检测到 Claude CLI，相关命令和解析通过替身进程测试，不等于 Claude 真机通过。
