# 验证范围与证据

> 来源：TeamFlow `teamflow-v1.0.0`，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`，原文件 `.agents/teamflow-core/references/CHECKS.md`。已将状态、命令与职责适配为 AgentWorks。 用户当前目标、平台和既有授权优先；版本号及商店/地区规则在实际执行时重新核对。

先读取实际工程与已有测试入口，选择覆盖本次风险的最小检查，再完成最终必要回归。记录真实命令/工具、工作目录、配置、超时、输入范围、开始结束时间、退出码、产物版本和日志位置。缺工具、没有测试或空命令都不能写通过。

将 AC 分成可自动检查与必须人工验证两类。无界面导入不证明玩法、视觉或真机；代码审查不替代运行。用户确认只适用于其实际确认的版本和条件。

证据复用前比较执行参数、工作目录、工具版本、输入内容（含新增/删除、执行位）、相关配置、需求范围/不包含/AC。检查运行中输入变化须重跑。提交前也核对待提交内容是否是受检内容；单有旧 commit 或成功日志不足以通过。

若业务工程已安装 TeamFlow 1.0 的 project-checks，可沿用 schema 2 profiles、extends、argv/cwd/timeout/inputs 及其证据指纹。AgentWorks 本次没有安装该执行引擎，不得声称其 fingerprint 门禁已自动生效。未接入时使用工程现有检查，报告上述输入与版本并由 QA 人工核对；无法建立对应关系时重跑。

原始日志保留在当前产品 app/ 下的构建/测试目录；报告引用相对路径和关键失败摘要，由主会话归档结果。失败证据不覆盖；辅助 Godot 检查默认缓存日志会覆盖，需跨轮追溯时主会话先按 run/task/ticket 归档，再执行新一轮。脱敏，不记录凭据和用户原始敏感数据。
