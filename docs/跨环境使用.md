# Codex 与 Claude 桌面端共用

正式使用方式是 Codex 桌面端，以及 Claude 桌面端的 Code 模式。打开同一份本地仓库，在聊天里启动团队；不需要独立命令行入口。

## 一份团队，两个入口

| 内容 | Codex 桌面端 | Claude 桌面端 Code 模式 |
|---|---|---|
| 共用规则 | 读取 `AGENTS.md` | `CLAUDE.md` 导入同一份 `AGENTS.md` |
| 原生子 Agent | `.codex/agents/*.toml` | `.claude/agents/agentworks-*.md` |
| 可选技能快捷入口 | `$agentworks` | `/agentworks` |
| 角色与流程来源 | `config/team.json`、`config/workflows.json` | 同一份配置 |
| 持久进度 | `.agentworks/` | 同一个数据目录 |

角色配置格式因平台而异，内容由一个来源生成，无需手动维护两份。`roles/*.md` 是共用角色卡，固定角色不可用时可交给当前平台的通用子 Agent。

两边都可以说：

> 使用 AgentWorks 查看当前项目，从已保存进度继续，使用当前桌面端的子 Agent 和工具完成任务。

## 桌面端准备

Codex 使用本地项目的主文件夹发现项目指令和角色。Claude 桌面端选择 Code 模式和本地项目目录，使用同一份项目指令与技能。根据官方文档，桌面会话可运行子 Agent，但具体权限和可用工具由应用和账号决定。[Codex 项目说明](https://learn.chatgpt.com/docs/projects)、[Codex 子 Agent](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[Claude Code 桌面说明](https://code.claude.com/docs/en/desktop)。

当前约定针对用户选定的 Claude Code 模式，未把普通聊天视为可以自动加载本地仓库角色的环境。

## 切换与共享

优先在两个桌面应用中选同一份原始本地文件夹。切换前收齐当前批次交付，再从保存状态继续；不同聊天的上下文不需要互相复制。

独立工作树会有不同文件路径，Git 忽略的项目数据不会因此自动复制。若桌面应用创建了工作树，让 Agent 指定原 `.agentworks/` 的绝对路径。未找到项目时先核对路径，不要自动另建同名项目。一个产品同时只交给一个总控批次，避免重复工作。

换电脑时同步仓库，再让 Agent 通过备份恢复项目数据。仅拉取 Git 不能取得已有产品的进度、原型和代码。

## 本次移除的部分

已移除独立终端应用入口、模型 CLI 后端适配、自动模型子进程调度和真实 CLI 调用脚本。没有登录检测、模型调用参数或终端启动操作。

保留 `agentworks.desktop.Workspace` 作为桌面 Agent 内部的保存与验收模块，负责任务登记、依赖、结果校验、重试、记忆和备份。它不运行模型，用户不需要操作它。内部调用见 [桌面内部接口](桌面内部接口.md)。

桌面原生工具不受旧后台适配的工具清单限制。可以使用当前会话已有的文件、浏览器、图像、终端和连接器能力，但仍受实际权限与用户授权约束。

实际验证范围见 [验收记录](验收记录.md)。
