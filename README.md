# AgentWorks

**在 Codex 桌面端和 Claude 桌面端 Code 模式中，通过聊天协作的海外产品团队。**

27 个固定角色、27 个职责技能、6 个阶段，从游戏与工具选题到产品、设计、独立评审、开发验收和运营迭代。所有角色采用20年资深从业者标准，这是专业判断框架，不是真实履历；AI用户评审明确标注模拟。角色按产品方向与阶段分工，明确不适用的任务记录原因。

## 直接开始

在 Codex 桌面端打开 AgentWorks 本地项目，或在 Claude 桌面端的 Code 模式选择同一份本地文件夹，然后说：

> 使用 AgentWorks 查看当前项目，从已保存进度继续。

新项目可以说：

> 使用 AgentWorks 新建海外产品项目，先比较游戏和工具，再按盈利证据选择方向。

你只需要聊天。团队使用当前桌面端的原生子 Agent 和工具，自动保存项目状态；不需要独立模型命令行、终端启动步骤或额外模型登录。

### 安装到产品仓库（推荐）

也可以把团队装进某个产品仓库，例如一个空的 `Cleaner` 文件夹。按当前打开的文件夹选择一种说法：

| 场景 | 在聊天里说 |
|---|---|
| 在 AgentWorks 会话中（推荐） | 把 AgentWorks 安装到 ~/Desktop/Cleaner。 |
| 在新文件夹的会话中，本机已有 AgentWorks | 运行 `python3 ~/Desktop/AgentWorks/scripts/install.py .`，把 AgentWorks 安装到当前文件夹，并告诉我改动了哪些文件。 |
| 在新文件夹的会话中，本机没有 AgentWorks | 把 `git@github.com:gzx543097079/AgentWorks.git` 的 v1.0.0 克隆到临时目录，运行其中的 `scripts/install.py`，安装到当前文件夹，并告诉我改动了哪些文件。 |

新文件夹里还没有 AgentWorks 规则，所以后两种需要告诉 Agent 源仓库的位置。也可以自己在终端运行：

```bash
python3 ~/Desktop/AgentWorks/scripts/install.py ~/Desktop/Cleaner
```

安装后**新开一个会话**再打开 `Cleaner`：角色、技能和 `CLAUDE.md` 只在会话启动时加载。然后说“使用 AgentWorks 新建项目，先比较游戏和工具，再按盈利证据选择方向”。

该仓库就是产品工作区，团队产出都按类别放在项目目录，可直接提交到 GitHub：

```
Cleaner/
├── docs/
│   ├── 项目简报.md  项目记忆.md  inputs/
│   ├── 01-discovery/  游戏机会.md 首批用户渠道.md 立项决策.md …
│   ├── 02-product/    需求文档.md 核心玩法.md 技术方案.md …
│   ├── 03-design/     原型说明.md 资深用户评审.md 评审裁决.md …
│   ├── 04-build/      测试报告.md 代码审查.md 开发验收.md …
│   ├── 05-launch/     发布方案.md 营销方案.md 上线验收.md …
│   └── 06-growth/     数据分析.md 下一轮实验.md …
├── design/   wireframe/ prototype/ ui/ art/ audio/
├── app/      源代码
├── release/  发布配置    store/  商店素材    marketing/  获客素材    support/  帮助内容
└── .agentworks/   状态库、任务包、执行凭据、确认记录和交付快照
```

`docs/inputs/` 中的真实用户资料和锁文件默认不提交。一个产品仓库对应一个项目。安装只在原有 `AGENTS.md`、`CLAUDE.md`、`.gitignore` 中追加带标记的区块；遇到同名的非 AgentWorks 文件会停止，不写入任何内容。AgentWorks 更新后，用同样的说法再安装一次即可升级；此版不兼容旧项目数据，采用新流程需新建项目，原数据保留。当前版本见 [VERSION](VERSION)，安装记录和 `AGENTS.md` 区块会写明已安装的版本号。

## 一份团队配置，两个桌面入口

| 内容 | Codex 桌面端 | Claude 桌面端 Code 模式 |
|---|---|---|
| 共用规则 | `AGENTS.md` | `CLAUDE.md` 导入同一规则 |
| 自动生成的原生角色 | `.codex/agents/agentworks-*.toml` | `.claude/agents/agentworks-*.md` |
| 启动方式 | 自然语言；可选 `$agentworks` | 自然语言；可选 `/agentworks` |
| 项目进度 | 同一份 `.agentworks/` | 同一份 `.agentworks/` |

角色及技能绑定只维护 `config/team.json`，流程只维护 `config/workflows.json`。技能正文、规范、脚本和素材只维护 `.agents/skills/`，同步到 Claude 入口，无需分别维护。

TeamFlow 1.0.0 的 42 份资源已按产品、UI、技术、开发、QA、本地化等职责分配，并补充海外 App 的订阅、隐私、ASO、增长和售后技能。分工、来源及使用方式见 [职责与技能](docs/职责与技能.md)。

## 协作流程

```mermaid
flowchart LR
    A[游戏与工具机会及证据审计] --> B[产品、领域、技术与验证方案]
    B --> B1[用户确认产品范围]
    B1 --> C1[低保真原型]
    C1 --> C2[用户确认原型流程]
    C2 --> C[美术音频与UI原型]
    C --> D[三位模拟用户独立评审]
    D --> E[产品裁决与设计修改]
    E --> F[独立原型验收]
    F --> F1[用户确认UI]
    F1 --> G[开发、测试、代码及安全审查]
    G --> H[修复、独立复核与回归]
    H --> H1[用户确认可运行构建]
    H1 --> I[发布、营销、销售与支持准备]
    I --> I1[用户确认发布方案]
    I1 --> J[真实数据、用户反馈与协作复盘]
```

六个工作流：`discovery → product → design → build → launch → growth`。运营从研究阶段就参与，阶段末有独立验收。结果待修改或阻塞时保留历史，补充输入后继续。

技术与安全初审先交付问题清单，开发者修复后分别复核；两项复核均通过，QA 才能完成开发验收。产品定义阶段明确哪些真人验证是原型或上线的必要条件，后续验收持续检查，不能把测试计划当成已验证需求。

产品范围、原型流程、UI、可运行构建和发布方案设有必要的真人用户确认。团队展示具体版本与预览后等待你的通过、修改或暂缓意见；完整工作授权和 QA 通过不能替代这些确认，文件变化后旧批准不能放行。

产品版本（如 `0.1.0`）、设计修订（如 `prototype-v3`、`ui-v2`）和构建编号（如 `build-007`）分别管理。每次交付保存独立快照，报告关联版本、实际产物和测试证据。

## 进度和交付长期保存

角色、流程、程序和说明进入 Git；报告、原型及代码在产品目录，状态、任务包、用户确认及 run/task/attempt 交付快照保存到 `.agentworks/`。

切换桌面端前先收齐当前批次交付，再打开同一份本地文件夹继续。原生子 Agent 开始前会登记任务，执行中不会被另一会话重复领取；中断后可以检查已有产物并恢复。工作树或另一台电脑需要明确连接或恢复原数据目录。

项目数据默认不进入 Git。你可以直接说“把这个项目备份到我指定的位置”，由 Agent 保存备份；恢复使用空目录，保留现有数据。

此版新项目使用新版确认与快照机制，不兼容旧项目数据；原数据保留，不自动迁移或覆盖。

## 桌面内部支持

`agentworks.desktop.Workspace` 只管理本地项目状态、交付校验、重试和备份，不调用模型。由桌面 Agent 使用自己的代码工具调用，用户无需操作。内部模块使用 Python 标准库，当前支持 macOS/Linux，依赖 Python 3.9+ 和 Git。

模型、并发能力、浏览器、图像和外部服务使用当前桌面应用的设置与已连接工具。缺少必需能力时明确报告。当前没有常驻服务；不会在关闭应用后自行另启模型进程。真实发布、对外消息或投放仍按用户明确授权执行。

维护人员与 Agent 参考 [团队运行手册](docs/团队运行手册.md)、[桌面内部接口](docs/桌面内部接口.md) 和 [协作约定](docs/协作约定.md)。

用户确认与评审会绑定实际文件；修改后共享输出目录的任务、受影响评审及批准失效。跨阶段修订归档旧下游阶段，重新验收后逐阶段继续。跨会话按 `status.current_stage` 定位当前有效阶段，历史批准和暂缓意见仍保留。
