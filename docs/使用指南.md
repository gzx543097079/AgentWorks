# AgentWorks 使用指南

AgentWorks 是本地可复用的海外产品团队。配置和代码进入 Git；每个产品的任务、报告和记忆保存在本机 `.agentworks/`。所有角色采用20年资深从业标准，这是角色设定，不是真实履历或真人身份。

## 在 Codex 中使用

打开本仓库项目，在新聊天中输入：

> 使用 AgentWorks 新建一个选题项目，同时比较海外游戏和工具，按需求证据、付费价值、获客渠道和验证成本选择方向。

后续可以说：

- 使用 AgentWorks 查看当前所有项目。
- 继续 first-opportunity，从已保存进度开始。
- 让三位模拟用户独立评审当前原型，由产品负责人汇总修改意见。
- 查看这个项目哪些结论有证据、哪些仍是假设。
- 为当前产品准备上线方案和第一轮增长实验。

项目规则在 `AGENTS.md`；技能入口是 `.agents/skills/agentworks/SKILL.md`。若当前聊天尚未刷新新技能，要求 Codex 读取该文件，或在此项目新开聊天。固定角色配置保存在 `.codex/agents/`。角色和技能的实际加载受 Codex 客户端版本影响；运行器直接读取 `config/team.json`，无需依赖角色选择界面。

## 本地运行入口

要求：macOS 或 Linux、Python 3.9+、Git。自动执行还需已登录的 Codex CLI。运行器只使用 Python 标准库，无需安装额外 Python 包。所有命令在仓库根目录运行。

```bash
python3 -m agentworks doctor
python3 -m agentworks roles
python3 -m agentworks workflows
```

新建项目并准备研究：

```bash
python3 -m agentworks create my-product --title "第一轮海外选题" --kind compare --market "先比较目标市场" --brief "游戏和工具均可，先找盈利证据再决定方向"
python3 -m agentworks plan my-product discovery
python3 -m agentworks run my-product
```

最后一条只预览，不调用模型。真正执行：

```bash
python3 -m agentworks run my-product --execute --max-tasks 2 --workers 2
python3 -m agentworks status my-product
python3 -m agentworks continue my-product --execute --max-tasks 3
```

`--max-tasks` 限制本次角色调用数量，默认1；`--workers` 默认2、最多3；单次角色运行默认超时900秒，可通过 `--timeout` 设置到最多3600秒。每项任务最多尝试3次。默认继承本机模型，可显式 `--model`。这些是调用数量和时间限制，不是精确金额上限；模型使用量与实际费用以账号记录为准。

研究默认开启实时搜索。若目标环境无法搜索，研究角色应报告缺口；`--no-search` 适合只处理已有资料的任务。

## 六个工作阶段

| 阶段 | 命令中的名称 | 交付 |
|---|---|---|
| 比较机会 | discovery | 游戏与工具机会、渠道、盈利假设与推荐 |
| 定义产品 | product | 用户任务、最小需求、玩法与测量方案 |
| 设计评审 | design | 原型、三份独立模拟评审、本地化、修改与验收 |
| 开发测试 | build | 可运行产品、独立测试、修复与回归验收 |
| 上线准备 | launch | 发布与恢复方案、推广材料、上线准备结论 |
| 运营迭代 | growth | 基于真实数据的分析、运营实验和产品迭代 |

当前阶段全部完成且验收通过后，用 `plan 项目 下一阶段` 进入下一步。这个系统可由对话中的总控连续推进，也可以逐阶段使用命令。研究后把选定方向写入 `BRIEF.md` 或项目记忆；如果多个方向尚未裁决，产品角色会明确指出。

launch 完成只表示准备完成。运行器不会自动发布生产、对外发消息或花钱投放。要执行这些操作，应在拥有对应连接工具的交互会话里给出具体授权，再保存真实执行结果。

growth 需要在 `input/` 放入真实数据及上线记录；没有数据时报告阻塞，不能伪造增长结果。图像生成、浏览器、Unity、设计工具或商业数据源按产品需要连接；登录 Codex 不意味着这些工具全部已连接。

## 看懂状态并继续

| 状态 | 含义 | 下一步 |
|---|---|---|
| ready | 依赖已满足 | 运行或导出任务包 |
| pending | 等待上游交付 | 先完成就绪任务 |
| running | 执行中 | 等待，不重复启动 |
| completed | 交付已保存；验收任务已通过 | 继续下游 |
| blocked | 缺少必须的输入或工具 | 补充后重试 |
| needs_revision | 独立验收要求修改 | 修改产物后重试验收，或重开本阶段 |
| failed | 进程、格式或工具执行失败 | 查看日志，修复后重试 |
| abandoned | 本轮已终止，历史保留 | 创建新一轮流程 |

```bash
python3 -m agentworks retry my-product 3 --reason "已补充必要的原始资料"
python3 -m agentworks continue my-product --execute --max-tasks 1
```

任务编号以 `status` 实际显示为准。重试会启动新的单角色会话，重载同一角色快照、项目资料及上游交付；不依赖隐藏聊天上下文，也不自动重复失败的外部动作。

需要让设计／开发重新处理修改清单时，将明确的修改要求写入项目记忆，然后 `abandon` 当前轮，重新 `plan` 同一阶段。验收角色不能为了通过而自行篡改验收结果。

```bash
python3 -m agentworks note my-product "依据验收报告，下一轮先修复首次使用流程；本条是产品决策。"
python3 -m agentworks abandon my-product --reason "保留本轮缺陷记录，重新设计"
python3 -m agentworks plan my-product design
```

如果机器或运行器意外退出，先确认残留工作进程已结束，再恢复状态：

```bash
python3 -m agentworks recover my-product
```

恢复会把未正常结束的任务标为失败，保留已有文件；检查之后再 retry。进程锁阻止同一项目的两个调度器重复工作。发现上次后台进程仍活跃时会拒绝恢复，避免两个开发者同时修改文件。

## 对话内执行与导入结果

无需在对话中再启动一个 CLI 运行器。总控可以将当前就绪任务包交给原生子 agent：

```bash
python3 -m agentworks packet my-product 1 --output .agentworks/packet-1.txt
```

让执行角色遵守任务包和 `config/result.schema.json`，将最终 JSON 保存为本地文件，然后：

```bash
python3 -m agentworks submit my-product 1 .agentworks/result-1.json
```

submit 验证依赖、状态、结果格式和产物文件是否存在。它无法自动证明调研结论真实或代码正确，后续仍由独立角色检查。

## 记忆、文件与备份

- `.agentworks/state.sqlite3`：项目、工作流、任务状态和事件。
- `.agentworks/projects/项目/workspace/BRIEF.md`：目标、约束及选题。
- 同一工作区 `MEMORY.md`：确认的偏好与决策；`input/`：原始资料、真实反馈和经营数据；`design/` 与 `app/`：产品交付。
- `.agentworks/projects/项目/runs/阶段编号/`：角色任务包、最终报告、JSON结果、执行日志。

整个 `.agentworks/` 默认不提交到远程。工作区有独立的本地 Git 边界，但不会自动提交或推送产品代码。以后正式立项时可为产品连接独立远程仓库。

```bash
python3 -m agentworks note my-product "目标市场改为英语用户，来源：用户确认"
python3 -m agentworks history my-product
python3 -m agentworks export my-product /你选择的备份目录/my-product.zip
```

备份包含项目状态、文件、报告和可能敏感的输入，应由你选择保管位置。它不读取 Codex 全局登录凭证，也不包含嵌套产品 Git 历史；工作区内的配置和日志会随项目导出。正式产品仓库另行备份。

恢复到一个空目录，避免覆盖现有项目：

```bash
python3 -m agentworks --data-dir /你选择的新数据目录 restore /备份目录/my-product.zip
python3 -m agentworks --data-dir /你选择的新数据目录 status my-product
```

恢复后继续使用相同的 `--data-dir`。更换电脑还需安装运行环境并重新登录、连接外部工具。

## 长期使用与持续在线

当前交付支持角色、流程和项目状态长期保存，新聊天、重启后可恢复使用。常驻服务尚未部署，关机时本机不会继续执行。

需要持续在线时，在你选择的常开电脑或服务器部署仓库和 Codex 运行环境，使用持久数据目录，并由系统服务调度有限任务批次。运行器返回非零状态时停止自动重试并查看原因；不要把无限循环当作长期运行。设置定时研究或监控的频率、预算和通知规则后，再安装具体服务。

## 修改团队

修改 `config/team.json`，再运行 `python3 scripts/sync_agents.py`。新工作流运行会保存当时的角色和流程快照；进行中的任务保持原版，便于复现。跨项目通用经验经过核实后再纳入规则，单个项目结论保留在该项目记忆中。
