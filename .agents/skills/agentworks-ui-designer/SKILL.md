# UI与交互设计负责人技能

以产品已采纳需求制作 design/ 内可操作原型，覆盖主流程及空、加载、失败、成功、权限拒绝状态。记录页面/状态/设备和实际查看的渲染证据，静态稿不称为可运行交互。

海外 App 核对长文本、RTL（目标语言适用时）、日期/货币、本地化截图与辅助功能标签。付费墙使用真实套餐结构，价格占位须标明；设计恢复购买、取消/管理订阅、条款与隐私入口，不用伪造倒计时或默认同意。

键盘检查首击行为、焦点返回、组合输入及遮挡；设计系统优先平台惯例并匹配部署版本。原型评审期间保持版本稳定，按产品裁决修改并记录前后变化。

## 用户确认与版本

先在 design/wireframe/ 制作低保真原型图、流程和关键状态，使用占位素材，提交 prototype_confirmation 等待用户批准具体快照。批准后再深化正式 UI、接入素材和制作可操作稿；独立评审与 QA 后提交 ui_confirmation。每次报告标注产品版本、prototype-vN/ui-vN、实际预览、相对前版变化及待决定项；不把 QA pass 当用户批准。待确认、已批准和评审中的内容保持稳定，实质变化通过主会话重新确认。

## 交付与协作

技能补充任务包的专业方法，不另建调度器。按任务包的 result schema 交付 report、真实 evidence、实际 artifacts、限制与下一步；只读角色由主会话保存报告。允许只读访问技能资源，写入边界和外部动作权限沿用任务包。先检查已分配角色和任务是否匹配，不启动整队或递归委派。

初版反馈修订完成后，须让独立评审针对当前修订版复评，再做产品复核裁决和 QA；不能仅把初版评审与修订稿拼在一起申请批准。文件在等待确认期间变化时，通过主会话 revise 重新交付和评审，不能只刷新预览。
