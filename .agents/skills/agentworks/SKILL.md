# AgentWorks 团队入口

工作目录为本技能所在仓库根目录。先读 [操作说明](../../../docs/使用指南.md)，只读取当前阶段需要的 [工作流约定](../../../docs/协作约定.md)。

## 启动与继续

1. 运行 `python3 -m agentworks status`，定位用户指定项目；未指定而只有一个项目时可以沿用，多个候选时询问项目。
2. 新项目用 `create` 保存用户目标；已存在项目先读 `status`、`BRIEF.md` 和 `MEMORY.md`。缺少预算先标未知，能完成的研究继续进行。
3. 使用 `plan` 建立用户所需阶段；前置阶段未通过时先处理缺项。用户授权使用团队完成一个产品时，可以按已通过的阶段继续推进，不重复请求常规步骤许可。
4. 根据可用工具选择一种执行方式：
   - **对话内协作**：为就绪任务导出 `packet`，读取其中对应角色；把独立任务委派给子 agent，受当前并发上限约束。若会话不支持固定角色名，传入完整任务包给普通 worker。要求按 `config/result.schema.json` 交付 JSON，主 agent 用 `submit` 保存并校验结果。
   - **本机运行器**：用 `run --execute --max-tasks N`；它调用本机 Codex CLI，依赖当前登录和额度。不要同时在对话和运行器里执行同一项目。
5. 每轮查看状态，检查关键交付文件和阶段结论，再推进。更新已确认决策用 `note`，不要仅留在聊天里。

## 角色及交接

角色源为 `config/team.json`，原生 Codex 配置为 `.codex/agents/*.toml`。只读当前任务需要的角色；全部角色按20年资深标准交付，不声称真实履历。

三位模拟用户评审独立接收同一个原型，不读取同轮其他评审。产品负责人负责反馈裁决，设计师和开发者按裁决修改，测试者独立验收。AI模拟意见始终标记为假设。真人访谈、使用数据和真实收入单独存入项目 `input/` 并注明来源。

单角色 worker 不再次委派；只写分配的产品目录。可写任务按顺序运行，避免覆盖；独立只读任务可并行。把共享交付物作为交接依据。

## 处理阻塞与范围

`blocked` 或 `needs_revision` 时解释具体缺项，先完成可独立进行的已授权工作。补充输入或修复后用带原因的 `retry`，最多3次；改变方向时保留历史并 `abandon` 当前阶段，再新建流程。不要为了通过验收把失败改成成功。

对外发送、投放、付费和生产发布需要用户明确授权；已有授权继续有效。运行器的 launch 流程仅准备材料。真实外部执行由拥有已授权连接的交互会话负责，并将操作结果写回项目。需要用户决策时展示具体可审阅交付物。

用用户能理解的语言汇报：交付了什么、证据在哪里、进度如何、具体缺什么。不要把正常的任务分发细节当作产品结果。
