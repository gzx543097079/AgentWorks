# 职责与技能

AgentWorks 保留一个团队、一个调度状态和六个阶段。TeamFlow 1.0.0 的需求、架构、编码、UI、测试、本地化、日志与发布方法已拆入职责技能；海外 App 方法直接补在各角色技能里。使用者照常聊天，任务包负责告诉执行角色读什么。

## 一份正文，两套入口

27 个角色是仓库内置团队，必须随 Git 一起提交。两平台原生角色统一命名为 `agentworks-<职责>`（内部 `role_id` 的下划线转连字符），例如 `technical_lead` 对应 `agentworks-technical-lead`。Codex 使用 `.codex/agents/agentworks-*.toml`，Claude 使用 `.claude/agents/agentworks-*.md`；同步会清理旧的已生成无前缀配置，避免重复角色。

- 唯一维护来源：`config/team.json` 的角色与 `skills` 绑定，`.agents/skills/` 的技能正文及支持资源。
- Codex 角色读取 `.agents/skills/`；Claude 对应正文、规范、脚本和素材同步到 `.claude/skills/`，两份相对目录一致。
- 共有 28 个技能入口：1 个团队入口和 27 个职责入口。角色配置里包含入口；`begin` 生成的任务包带当前角色的绝对入口与本技能目录资源 SHA-256，宿主未自动加载技能也能明确读取。
- 只按实际平台/任务读取支持资料，iOS 与 Godot 规范不强加给其他技术栈。角色复用其他职责拥有的规范链接，不维护第二份权威内容。
- 同步清单只管理本项目生成的技能文件，保留其他自定义文件；同名未受管理文件冲突时先保留并报告。维护由 Agent 完成，使用者不需操作终端。

## TeamFlow 内容归属

固定来源：[iOS_TeamFlow 的 teamflow-v1.0.0](https://github.com/gzx543097079/iOS_TeamFlow/tree/teamflow-v1.0.0)，提交 `e2088f01b7834ca1cf7217004309fe0cb22ee3bc`。共分配 42 份资源（36 份规范/模板、3 个辅助脚本、3 个日志源码）。[来源清单](../config/teamflow-sources.json) 记录原路径、原文 SHA-256、责任角色、落地路径及未安装内容，便于后续按版本比较更新。

| 内容 | 主要负责人 | 具体落地 |
|---|---|---|
| 工作流与边界 | 总控 | 需求范围、人工 AC、状态推进、授权与交接；适配现有 ticket |
| 需求、新工程、功能模板 | 产品 | 编号、范围、不包含、验收方式与版本 |
| 架构、依赖、既有工程、模块上下文、评审 | 技术负责人 | 真实调用链、模块职责、迁移与独立复核 |
| Swift/SwiftUI/Objective-C、GDScript、生命周期、注释 | 开发 | 按实际语言/平台读取并实现 |
| 日志规范与源码、安装辅助工具 | 开发 | 分级、脱敏、Debug/Release、构建目标接入 |
| UI、键盘、付费墙 | UI | 界面状态、输入、无障碍；开发和 QA 引用同一规范 |
| 检查证据、Godot 测试、iOS/Godot 性能 | QA | 当前版本证据、自动/人工区分、导入与真实测试 |
| 引擎与场景规则 | 游戏策划 | 核心玩法、场景与资源约束，供开发及关卡引用 |
| 多语言及 iOS 资源 | 本地化 | 语义 key、复数、全部启用语言和界面实测 |
| App 外部动作、Godot iOS 导出与发布模板 | 发布 | build 绑定、实际模板架构、审核和发布边界 |
| 缺陷与流程改进 | 协作质量 | 复现与证据驱动的最小改进，避免重复台账 |

原安装、升级、权限文件、顶层 req/Git/CI 调度与原入口未整套安装。它们绑定 TeamFlow 原目录和状态；相关方法已适配上述职责。AgentWorks 不声称拥有 TeamFlow 原 project-checks 的自动指纹门禁，也不覆盖桌面权限或产品原有工作流。

辅助工具由桌面 Agent 在实际任务需要时调用：日志安装保护既有定制；Godot 验证需要真实工程与测试脚本；Godot 导出只写游戏根 build/ 下全新目录，保留旧构建，不上传。导出由有写权限的开发任务/主会话执行，发布角色保持只读。

## 版本、日志与交接

技能和配置随仓库 Git 保存；产品结果仍在 `.agentworks/projects/<项目>/`，本次不迁移或覆盖旧数据。阶段保存角色/任务快照，每次桌面尝试另存 ticket、任务包和结果。报告应关联需求/AC、产物版本、测试环境、证据路径、未决项和下一负责人。原始测试日志在产品 app/ 内，主会话按 run/task/attempt 归档需长期保留的证据，不能用同名覆盖日志充当历史证据。

技能文件内容本身没有随阶段完整封存：任务开始保存本技能目录资源指纹，跨角色引用仍跟随仓库版本。交接时记录 AgentWorks 仓库提交及本地修改，固定同一检出再恢复；需要完整重放时同时备份该检出与产品数据。指纹是审计信息，当前不会自动阻止运行期间的技能修改，也不替代 TeamFlow 的测试输入指纹门禁。

已存在的旧阶段没有技能字段仍可继续，任务包不悄悄换新版角色。要采用新版分工，先收齐/停止旧执行，保留原记录，再重规划阶段。即使旧任务技能为空，也只按原任务执行，不能因为当前角色模板有技能而改变旧范围。

## 使用示例

> 使用 AgentWorks 开始新的海外工具 App 项目。按角色职责技能推进，产品先给范围和验收条件；开发按选定平台实现，QA、技术和安全独立复核。

> 继续当前项目，核对所用版本、未完成 AC 与下一负责人；不要把模拟用户意见当作真人验证。

团队入口、两平台配置和测试通过只能证明配置与交接机制成立。真实桌面子 Agent 是否正确加载、专业交付质量、真实 App 构建和市场成效需在实际任务中验证。验收范围见 [验收记录](验收记录.md)。
